## 1. التشخيص المختصر (ما تم رصده في الكود)

- **ازدحام التنقل في الواجهة (`apps/web/src/app/page.tsx`):** 4 طبقات متداخلة في نفس الوقت (القائمة الجانبية + مبدّل `WorkspaceMode` مدرب/محلل/كشاف + شريط الخطوات الـ 3 + قائمة الدور `role` + أزرار التقارير + شريط شرائح المباريات الطويل)، بالإضافة لشريط `Panel Presets` داخل الاستوديو.
- **سكرول طويل مكدس في `BroadcastStudioScreen.tsx` (2,907 أسطر):** 5 أقسام ضخمة تتكدس عمودياً تحت الشبكة الرئيسية (`2501`–`2907`): الزخم واللحظات، تشريح الفريقين، مقاييس OBV/xPass، التكويد وقوائم التشغيل، ومرسم الخطط الـ 22 لاعباً.
- **أرقام وبيانات غير صادقة أو مضللة:**
  - `apps/api/service.py:1132-1138`: اختراع أرقام قمصان (`(idx % 11) + 2`) وأسماء مثل `لاعب الأهلي #7` عند غياب المطابقة.
  - `apps/api/service.py:3246`: إرجاع `has_external_api_key: True` بشكل ثابت دائماً.
  - `apps/api/service.py:3234-3239`: أسئلة متابعة محفوظة مسبقاً (`3-5-2 تيكي تاكا`) غير مرتبطة باللقطة.
  - `apps/web/src/app/page.tsx:37-74`: مصفوفة `FALLBACK_MATCHES` تعرض مباريات وهمية لو السيرفر متوقف.
  - `apps/api/service.py:482`: افتراض أبعاد فيديو ثابتة `1264x705` أثناء تقييم لقطات اللاعبين.
  - نصوص تسويقية/تقنية داخل الواجهة (`V8`، `V9.5`، `Wave`، `Sec`، `PDF Pages`، `100%`، `Math-First`، `Oracle`، إيموجيهات).

- **الميزة التوقيعية الناقصة:** يوجد قص مبدئي (`render_track_crop_jpeg`) لكن لا توجد شاشة لاعبين، ولا كارت لاعب احترافي بنمط FIFA/Fantasy بأفضل لقطة واضحة، ولا رفع صورة، ولا تصدير `PNG`، ولا مقارنة لاعبين.

## 4. مواصفات كارت اللاعب (FIFA / Fantasy FUT Honest Spec)

- **الشكل والأبعاد:** درع FUT كلاسيكي بحواف علوية مشطوفة/منحنية وقاع مدبب عبر `SVG clipPath` في React ونفس المسار في Canvas (`1080×1540`، نسبة ~`0.70`).
- **التكوين البصري:**
  - زاوية البداية العليا: **رقم القميص** بخط بارز (أو `—` إذا كان غير مؤكد)، أسفله رمز المركز (`GK / CB / LB / RB / CM / LM / RM / ST / LW / RW`)، وأسفله شارة دائرية بلون القميص وبأحرف الفريق.
  - منطقة الصورة: أفضل لقطة واضحة من الفيديو (أو صورة مرفوعة) في النصف العلوي تتلاشى بنعومة مع خلفية الكارت.
  - شريط الاسم: الاسم بخط عريض واضح، مع شارة صغيرة `غير مؤكد` عند عدم التحقق.
  - **شبكة `2×3` للسمات الـ 6 (مئينات داخل المباراة `0–99` + القيمة المقاسة الحقيقية أسفلها):**
    1. `SPD` / سرعة: السرعة القصوى `p95` (`km/h`)
    2. `DST` / مسافة: المسافة المقطوعة (`m`)
    3. `WRK` / جهد: معدل الجهد (`m/min`)
    4. `SPR` / انطلاقات: عدد الانطلاقات `≥ 25 km/h` لمدة `≥ 1s`
    5. `AVG` / متوسط: متوسط السرعة (`km/h`)
    6. `MIN` / دقائق: زمن الظهور الفعلي في الفيديو
- **الصدق المطلق (Zero Fake OVR):**
  - ممنوع أي تقييم إجمالي (`OVR` / `rating`).
  - تذييل الكارت: «الأرقام = ترتيب اللاعب داخل هذه المباراة (0–99) • مقاسة من X ث فيديو».
  - **لون الكارت (Tier) = درجة ثقة البيانات:**
    - **ذهبي (Gold):** `calibrated_ratio ≥ 0.8` و`observed_s ≥ 60` (`#F5D77A → #B8862B`)
    - **فضي (Silver):** `calibrated_ratio ≥ 0.5` و`observed_s ≥ 20` (`#E5E7EB → #8B95A5`)
    - **برونزي (Bronze):** دون ذلك (`#E3A76F → #8A5A2B`)
  - في حال وجود أقل من 3 لاعبين بإحصائيات مترية صالحة داخل نفس المجموعة، تُعرض القيم الخام بدون اختراع مئينات.

## 6. علامات التوقف وإعادة التخطيط (Re-plan Triggers)

- غياب الإحداثيات المترية (`x_m / y_m`) أو التوقيت الزمني في ملفات Parquet بحيث يتعذر حساب إحصائيات مقاسة بصدق.
- وجود فشل واسع في الاختبارات الأساسية أو البناء قبل بدء التعديلات.
- تعطل حالة مرسم الخطط أو استقبال `externalBlueprint` عند تحويل أقسام الاستوديو لتابات.
- وجود أقل من 3 لاعبين بإحصائيات صالحة لدرجة تمنع حساب المئينات في المباراة (نكتفي حينها بالقيم الخام ونبلّغ).
- عدم قدرة أداة المتصفح على فتح التطبيق بعد تأكيد عمل الخادمين.
